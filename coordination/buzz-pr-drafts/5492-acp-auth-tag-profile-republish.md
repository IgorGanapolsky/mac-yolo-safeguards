**Title:** `fix(acp): reconcile own kind:0 with BUZZ_AUTH_TAG at startup`

Fixes #5492.

## Problem

`BUZZ_AUTH_TAG` only changes events the agent signs from that point on — it never touches the kind:0 profile the relay already holds. The sibling gate (`check_sibling_via_profile`) verifies a peer against that *stored* profile, so a headless agent whose profile predates its attestation is silently unverifiable to its siblings: the relay accepts a sibling's mention and the peer's author gate drops it, with no error on either side.

The documented workaround — `buzz users set-profile` — works precisely because `BuzzClient::sign_event` injects the auth tag into everything it signs, including the kind:0 it republishes. `buzz-acp` has no equivalent step, so it never reconciles.

## Fix

Query our own kind:0 at startup and republish it carrying the auth tag when the stored copy does not already prove the owner.

- **Content preserved verbatim** — display name, avatar, and any profile fields this crate does not model survive the rewrite.
- **Idempotent** — a profile that already proves the owner publishes nothing, so restarts do not re-sign a kind:0 on every boot.
- **Generalizes** — covers later causes of the same skew (tag rotation, relay migration, a profile restored from a backup older than the attestation), rather than only the first-provisioning case.
- **Best-effort** — a query or submit failure logs and startup continues, matching the previous behaviour where the profile simply stayed stale. A relay that cannot serve the query is not a reason to refuse to run.

The tag-verification predicate is extracted into `profile_tags_prove_owner` and shared with the inbound sibling gate, so both sides agree by construction on what "this profile proves that owner" means. If those two ever drifted, an agent could consider its own profile acceptable while its siblings rejected it — which is exactly the failure this reconciliation exists to prevent.

## Tests

Seven unit tests in `profile_auth_tag_reconcile_tests`, using real signed NIP-OA attestations (`compute_auth_tag`) rather than hand-written fixtures, so they exercise the same verification the sibling gate performs:

| Test | Asserts |
|------|---------|
| `untagged_stored_profile_needs_republish` | the reported bug — env var set, stored profile untagged ⇒ republish |
| `absent_stored_profile_needs_republish` | no profile on the relay ⇒ republish |
| `correctly_tagged_stored_profile_is_left_alone` | idempotency — already-proving profile ⇒ no republish |
| `auth_tag_for_a_different_owner_needs_republish` | another owner's attestation is not proof for this owner |
| `forged_auth_tag_signature_needs_republish` | relay is not trusted — bad Schnorr signature ⇒ republish |
| `owner_hex_is_compared_case_insensitively` | casing differences do not cause spurious republishes |
| `malformed_tags_field_needs_republish` | missing / wrong-typed `tags` proves nothing |
