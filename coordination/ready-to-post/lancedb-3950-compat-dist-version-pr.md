Fixes #3950.

## The failure

`lancedb/__init__.py` resolved `__version__` with a hardcoded lookup:

```python
__version__ = importlib.metadata.version("lancedb")
```

The same import package is also published to PyPI as the `lancedb-compat` distribution, whose wheel
registers metadata under the `lancedb-compat` name only. Installing it standalone makes
`import lancedb` fail outright — not a wrong version string, a hard crash on the very first import:

```
importlib.metadata.PackageNotFoundError: No package metadata was found for lancedb
```

## Before / after

Reproduced against the real published wheel (`pip install lancedb==0.37.1` in a clean venv, then
renaming its `.dist-info` to `lancedb_compat-0.37.1.dist-info` with `Name: lancedb-compat` — i.e.
exactly the metadata layout a standalone `lancedb-compat` install produces):

**Before:**
```
$ python -c "import lancedb"
...
importlib.metadata.PackageNotFoundError: No package metadata was found for lancedb
```

**After:**
```
$ python -c "import lancedb; print(lancedb.__version__)"
0.37.1
```

## The change

The lookup moves into `lancedb/_version.py` and falls back to the `lancedb-compat` dist name when
`lancedb` is not registered. The normal `lancedb` install path is unchanged and is still tried
first, so nothing changes for the common case. If neither distribution is installed, Python's
exception chaining surfaces both attempted names in the traceback.

The issue also floated a build-time `_version.py` generated by maturin as the preferred fix. I went
with the runtime fallback because it is self-contained in the Python source and needs no
build-system change; happy to redo it as a generated file if you'd rather remove the runtime
metadata dependency entirely.
