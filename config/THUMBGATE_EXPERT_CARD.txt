[PRODUCT]
ThumbGate.app is the free browser control plane (Web Control) for Hermes coding agents running on your Mac: chats, machines, Leash tool approvals, signed P-256 machine pairing.
Paid SKU is Continuity: when the Mac goes offline, ELIGIBLE work continues on a fenced Fly VPS runner (queued prompt/thread handoff, 90s fenced lease). It is NOT live process migration.
It complements Hermes Mobile (paid native app, $4.99 pay-once, Play + App Store). It is never a workaround for mobile connectivity failure.
SKUs (live readback): Web Control $0/mo; Pro Continuity $10/mo (100 cloud continuations/30d, model routing, 14-day trial with 5 cloud runs); Team/Enterprise $49/mo (500 continuations, BYO key, priority runner).
Pro price is dynamic from https://thumbgate.app/api/billing/plan — re-read before any campaign; never hard-code the price in copy.
Surfaces: thumbgate.app, app.thumbgate.app, /llms.txt, /.well-known/ai-catalog.json, /go/android, /go/ios.
Stack: Cloudflare Worker + D1, WorkOS AuthKit, Stripe, Fly runner. Keep this stack; no rewrites.
ThumbGate.ai (Self-Improving Firewall, $19 Pro) is a SEPARATE product — never conflate the two.

[BUYER]
ICP: solo dev running coding agents; security engineer; startup CTO; DevOps/platform engineer; Mac agent operator; Cursor power user; Claude Code user.
Pains (cited in research): runaway agent loops and overnight token burn ($47k 11-day loop on dev.to, $6,531 AWS bill on HN, PocketOS prod-DB deletion); no control when away from laptop; credentials/code leaving the machine (GitGuardian 28.6M leaked secrets); need pre-execution human gate on destructive tool calls, not post-hoc review; IDE-local control dies when you leave Cursor; Mac offline means agent stops.
Buyer wants local-first privacy: local execution stays free; the Mac stays primary.

[POSITIONING]

Category white-space: own "Mac is primary; pay only for offline continuation" AND more durably "human-in-the-loop gate for unattended agents" (the gate is orthogonal to where the agent runs).

[PROMO_RULES]
Sell Continuity as an add-on, never as a fallback for a broken app (PR #1075). Rescue language fails the regression gate: "phone cannot reach", "pair a Mac and continue", "replacement", "instead".
Never say: fixes/repairs mobile connectivity or pairing; replaces Hermes Mobile; hard-coded dollar price in campaigns; "always works"; "seamless failover"; "agent never stops"; "same tools as Mac"; "guaranteed uptime" without a published SLO; "E2EE" or "fully private" (snapshots are not E2EE); "making money" without provider proof.
Do say: "eligible work"; "optional paid Continuity"; "queued prompt handoff, not process migration"; "fenced VPS"; "auto or ask-first offline policy under your control".
30 days of canary metrics before any stronger reliability language; publish canary/SLO stats instead of adjectives.
Analytics never send prompts, chat bodies, credentials, device keys, emails, IPs, cookies, or user agents.
Evidence rule: first-party URLs and live billing endpoints outrank deep-research prose (a research run once declared ThumbGate.app nonexistent and pitched the wrong $19 product).

[SALES_MOTION]
Mobile funnel: promo view -> tap (UTM) -> /dashboard workspace (Leash/chats) -> Continuity/billing only when user needs offline failover -> 14-day trial (5 cloud runs) -> active paid subscription. Pricing is secondary, never the default entry.
Web funnel: landing -> sign-in -> authenticated landing -> first chat visible -> pairing started -> pairing approved -> failover enabled -> checkout -> paid subscription confirmed.
Activation: WorkOS sign-in -> one copyable installer command -> auto-opened prefilled pair URL -> explicit approve of named Mac (zero code transcription) -> connector reads local Hermes key (never copied off-machine) -> newest chat auto-opens. Target P50 first real chat under 180s (acceptance target, not yet measured).
Operating metric: install is step 0, pair is step 1, first chat is the product. Pair -> first chat -> first real approve/deny is what counts, not store installs.
Paid users default failover_mode=auto so Continuity actually fires; denied claims fail to recoverable offline_blocked.
GTM checklist: public canary/status page; hero stack = free dashboard (Leash/gate) -> optional Continuity -> store badges -> pairing diagram; design partners for gate value, not Continuity-only outreach.
